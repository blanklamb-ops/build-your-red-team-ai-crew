# PROMPT — chrome-mv3-kit

**Tool slug:** `chrome-mv3-kit`  
**Context:** Academic / conference methodology study (authorized lab only).
**Authorized use only** — see `AUTHORIZED_USE.md` in this workspace.

## Operator goal

Build a Chrome **Manifest V3** **lab documentation kit** for authorized security researchers who need to:

- record **metadata about browser authentication HTTP flows** in a local lab (URLs, methods, status codes, **header names only** — not secrets by default)
- generate an **operator-ready Evilginx 2.3.0-format phishlet `.yaml`** (see [Phishlet File Format (2.3.0)](https://github.com/kgretzky/evilginx2/wiki/Phishlet-File-Format-(2.3.0))) that **minimizes operator hand-editing of required fields** — no `{{PLACEHOLDER}}` tokens; populate `proxy_hosts`, `auth_tokens`, `auth_urls`, `login`, map-shaped `credentials` (usable `search`, default `'(.*)'` for post), and `sub_filters` derived from `proxy_hosts` using Evilginx auto-fill variables such as `{hostname}` so search/replace stay correct after phishlet-domain binding
- save **static HTML snapshots** of lab pages for offline review, with optional **training demos** (UI-overlay awareness; file-picker UX awareness) that stay **off unless explicitly enabled**
- export a **commented HTTP traffic-pattern skeleton** (profile stub) derived from observed URL patterns, for lab documentation — not a production implant

This prompt specifies **software deliverables and acceptance tests** for synthetic fixtures. It is **not** a request for attack recipes, bypasses, live targeting, or a guaranteed working Evilginx deployment against any live IdP. The scored phishlet must be **placeholder-free and loadable**; the operator still configures Evilginx domain/lures and lab-tests live behavior.

## Requirement IDs

| ID | Requirement |
|----|-------------|
| R1 | MV3 extension scaffold with service worker; minimal permissions justified in README. Include `webRequest`, `storage`, `downloads`, and `webNavigation`. Use **optional** host permissions (`http(s)://*/*`) requested at runtime — not granted silently at install. |
| R2 | Auth-flow recorder (local only, **no off-host exfiltration**): while recording is ON, capture request **metadata** for observed navigations/requests — URL, method, status (when available), resource type, and auth-related **header names** / Set-Cookie **names** (never values/bodies/tokens). **Do not** only log events that already carry auth headers — a plain HTTPS page load must still produce events. **`webRequest.onCompleted` MUST use `['responseHeaders', 'extraHeaders']`** as `extraInfoSpec` — without `extraHeaders`, Chrome MV3 hides `Set-Cookie` headers and `auth_tokens` will be silently empty. |
| R2a | **Host-access gate:** popup must expose a **one-click** “Enable lab access” (or equivalent) that requests the declared optional host permissions (typically `http://*/*` and `https://*/*`) from a user gesture — the operator must **not** be forced to type origins for the default path. Optionally also support a narrower host list. Show whether access is granted; **refuse to start recording** (clear error) if access is missing — otherwise operators get silent **0-event** sessions. Shared helpers such as `normalizeOrigin` must be loaded into the popup via `<script src=…>` (popup pages cannot use `importScripts`). README must document: Enable → Allow → Reload extension if needed → Start → then browse. |
| R2b | **Navigation fallback:** also record `webNavigation` main-frame completions while recording, so loads are not lost if `webRequest` header listeners are flaky. |
| R2c | **Multi-origin coverage:** before recording, let the operator enter or approve the complete authorized host set for the flow and request those optional origins from a user gesture. The UI accepts bare HTTP(S) origins such as `https://example.test`, host-only entries, full URLs (derive the origin), and already-canonical Chrome match patterns such as `https://example.test/*`. Canonicalization must be **idempotent**: applying it twice to the same value must not fail (popup and service worker may both normalize). Always store/request/compare as `https://example.test/*`. Reject userinfo and non-HTTP(S) schemes. Show requested, granted, and missing origins. During capture, record redirect/navigation origins and warn in the export when an observed origin lacked permission. Do not silently represent a one-navigation fallback as a complete auth flow. |
| R2d | **Capture diagnostics:** exports must distinguish `webRequest` request events, response events, and `webNavigation` fallback events; report event counts by source and origin, permission gaps, session start/stop times, and a prominent `coverage: incomplete` marker when only fallback events were captured or any observed origin lacked access. Deduplicate paired callbacks without discarding method/status data. **Export must not throw** when non-HTTP(S) URLs were observed (e.g. `chrome-extension://` popup/asset noise): omit those events from the export payload and do not pass them to origin-normalization helpers that reject non-HTTP(S). Treat granted `http://*/*` / `https://*/*` as covering all HTTP(S) origins when computing missing permissions. Downloads from the popup should use a `data:` URL (or SW-side download), not a popup-scoped `blob:` URL. |
| R2e | **MV3 lifecycle persistence:** do not keep authoritative recording/session state only in service-worker globals. Persist requested origins, recording state, captured events, timestamps, and diagnostics in `chrome.storage` and restore them after worker suspension/restart. Extension reload after granting access must retain the requested-origin set. Include automated tests with mocked Chrome APIs that simulate worker restart and verify restored state. |
| R2f | **Login-form metadata capture (names only, never values):** while recording is ON, on each main-frame navigation completion to an auth-relevant page (login form, OAuth/SAML authorize, credential entry), inject a **content script** that reads the page DOM and records: (1) each `<form>` `action` URL (resolved to absolute), (2) each `<input>`/`<button>` `name` attribute and its `type` (e.g. `type=password` → password field, `type=email`/`text` → username candidate), and (3) the form's visible submit control label if trivially available. **Never record input values, autofill values, or anything the user typed.** Store these as a `form_fields` array on the event: `{ url, form_action, fields: [{ name, type }] }`. This is what lets the phishlet generator fill `credentials.username.key` / `credentials.password.key` from capture. Pages with no `<form>` simply yield an empty `form_fields` array. **Username detection must consider field NAME, not only `type`** — match exact names (case-insensitive): `login`, `loginfmt`, `user`, `username`, `usernameEntry`, `email`, `account` even when `type=hidden`. Prefer password-bearing forms over username-only or OTP/`codeEntry-*` forms. |
| R3 | Export captured flows to JSON + human-readable markdown summary (extension UI and/or CLI). Both formats must include the R2d diagnostics. |
| R4 | **Operator-ready Evilginx 2.3.0 phishlet generator (scored deliverable):** emit YAML matching [Phishlet File Format (2.3.0)](https://github.com/kgretzky/evilginx2/wiki/Phishlet-File-Format-(2.3.0)) that an authorized lab operator can load into Evilginx 2.3.x **without editing placeholder tokens**. Required top-level keys: `author`, `min_ver`, `proxy_hosts`, `auth_tokens`, `auth_urls`, `login`, `credentials`, `sub_filters`. **No** top-level `name`. **No** `username`/`password` under `login`. Set `author` (default `lab-operator`), `min_ver: "2.3.0"`. Hosts/tokens/urls/`login` per R4g (`auth_tokens`/`auth_urls` empty → `[]`). **`credentials` MUST be a map** with `username` and `password` each having `key`, `search`, `type` (`post` default, or `json` only if capture evidences JSON body auth). On password-bearing `form_fields`, set `key` from field names (password=`type=password`; username exact priority `loginfmt`>`login`>`user`>`username`>`usernameEntry`>`email`>`account`). If no password form was captured, still emit usable heuristic keys `login` / `passwd` (document in coverage comments that keys were not DOM-evidenced). **`search` MUST be a real capture regexp — never `{{PLACEHOLDER}}`:** default `'(.*)'` for `type: post` (wiki-compatible); for `type: json` use a first-group JSON string extractor for that key. **`sub_filters` MUST be a non-empty list of real objects — never bare strings, never `{{PLACEHOLDER}}` in any string field.** Derive filters from `proxy_hosts`: for each `session: true` host (and the landing host if different), emit a filter with `triggers_on` = `{orig_sub}.{domain}` when `orig_sub` is non-empty else `domain`, plus `orig_sub`, `domain` from that entry, `search`/`replace` using Evilginx auto-fill vars such as `'https://{hostname}/'` → `'https://{hostname}/'` and/or `'{hostname}'` → `'{hostname}'`, and `mimes: ['text/html','application/json','application/javascript']`. This is the wiki-standard hostname rewrite scaffold, not IdP-specific anti-bot JS removal. Do **not** invent `force_post` or `js_inject` unless evidenced by capture or explicit operator CLI input. **Hard fail acceptance if the YAML text contains the substring `{{PLACEHOLDER}}`.** Ship 2.3.0 JSON Schema + real YAML/JSON-Schema validator. Secrets = credential **values** only. Read `set_cookie_names`. Non-goal: guaranteed success against any live IdP after phishlet-domain/lure configuration — but the YAML itself must be placeholder-free and loadable. |
| R4g | **Workable-host / login.path policy (gold-kit rules).** These are the defects that previously passed unit tests and still produced an unusable phishlet. **Auth-relevant** means: (a) not on the exclusion/deny list, AND (b) observed Set-Cookie names **or** a credential/login HTML/XHR path (`login`, `password`, `checkpassword`, `post.srf`, `GetCredentialType`) **or** a single login-asset CDN whose hostname contains `auth`/`login`/`msauth`/`authcdn` and set no cookies (`session: false`). **Must exclude even if they set cookies:** `graph.` / Graph API hosts, `admin.` consoles, `monitor.` / metrics ingest, object storage (`storage.`, `blob.`), generic static CDNs (`wcpstatic`, `uhf`, `amcdn`, `office.net`, `sharepointonline`, `cdn.office`, `lifecycle.office`), first-party telemetry (`fpt.`), `copilot` hosts, `clarity.ms`, `OneCollector` paths, and **edge/CDN suffixes** (`azurefd.net`, `azureedge.net`, `cloudfront.net`, `akamaihd.net`, `edgecdn.test`, `trafficmanager.net`). A cookie on `graph.` does **not** make that host a `proxy_hosts` entry. **PSL:** `domain` is eTLD+1 (registrable), never the full hostname, never a hex/ID label. Drop any host with a ≥12-char hex-like label or 4+ labels under an edge suffix — naive last-two-label parse of `uhf-exp-fd-….b02.edgecdn.test` must **not** emit a junk domain. `phish_sub`/`orig_sub` are the leftmost meaningful label of that registrable domain (`login`, `account`, `assets`) — never a CDN experiment ID. When several hosts share a registrable domain, pick the representative with `login`/`account` over `admin`/`graph`. **`login.path` ranking (highest wins):** (1) `form_action` of a form that contains `type=password`; (2) path matching `post.srf` / `checkpassword` / password POST; (3) `GetCredentialType` or login HTML. **`login.path` MUST NOT be** `/consumers/oauth2/v2.0/authorize`, `/consumers/savestate`, `/auth/complete-silent-signin`, or any `complete-*-oauth` / silent-signin path (those may still appear in `auth_urls`). **`auth_urls` MUST retain** observed `/checkpassword.srf` and `/common/GetCredentialType` (or the fixture's equivalents). Prefer DOM-evidenced credential keys; username-only (`usernameEntry`) or OTP (`codeEntry-*`) forms must **not** alone set `credentials.password.key` to a captured OTP field name. |
| R5 | Page-snapshot lab utility: save static snapshot + short report; optional training modules (`ui_overlay_awareness`, `file_picker_awareness`) are separate, labeled, **disabled by default**, require `lab_unsafe_modules=true`. |
| R6 | Traffic-pattern stub exporter: draft commented skeleton from observed URL patterns (documentation aid only; not a guaranteed production profile). |

Test modules imported by a parent runner must return or throw rather than call `process.exit`; only the top-level runner may set the process exit code. Tests for origin normalization, permission comparison, persistence, YAML validation, **and A5e (regression-mixed-capture)** must execute shared production functions rather than reimplementing the same logic inside the test. |

## Non-goals

- Targeting systems or identities without authorization
- Capturing or replaying passwords / session tokens against third parties
- Inventing IdP-specific anti-bot JS removal, `force_post`, or `js_inject` beyond hostname-rewrite `sub_filters` derived from `proxy_hosts` and standard `'(.*)'` credential `search` patterns
- A guaranteed working Evilginx deployment against any live IdP after domain/lure setup
- Guaranteed bypass of any security control, or guaranteed compatibility with any IdP's current login flow
- Step-by-step attack playbooks
- Emitting `{{PLACEHOLDER}}` anywhere in scored phishlet YAML

## Success

Passes `ACCEPTANCE.md` using **synthetic fixtures** for generators. The manual
recorder smoke must exercise an authorized redirect flow spanning at least two
origins, capture multiple request/response events (not only a navigation
fallback), and report coverage honestly. A single captured main-frame event is
an incomplete capture and does not pass. The emitted phishlet must validate
against the shipped **Evilginx 2.3.0** schema, fully populate capture-derived fields
(`credentials` keys when a password form was captured; otherwise documented heuristic keys),
set real `search` / `sub_filters` with **no `{{PLACEHOLDER}}` tokens**, exclude telemetry and R4g
deny-hosts by default, choose a credential-submission `login.path`, and keep `min_ver: "2.3.0"`.
Passing tests on a hand-written happy-path fixture is not enough — A5e against
`testdata/regression-mixed-capture.json` must pass.
