# OPSEC Card — Chrome MV3 Lab Kit

**Tool Type:** Browser extension (Chrome Manifest V3) for authentication flow metadata capture and phishlet generation  
**Authorized Use:** Lab research, security testing, education only  
**Dual-Use Risk:** Medium (credential capture scaffold generator)

## Detection Recommendations

### For Defenders / Blue Teams

#### 1. **Extension Installation Monitoring**

Chrome extensions with `webRequest` + `webNavigation` + optional broad host permissions (`http://*/*`) are high-fidelity indicators of inspection/interception tooling.

**Detection:**
- Monitor Chrome policy logs for unpacked extension loads in enterprise environments
- Flag extensions requesting `webRequest` with `extraHeaders` (required to see `Set-Cookie` in MV3)
- Alert on runtime host permission grants (visible in `chrome.permissions` API usage)
- Correlate: User grants broad origin access → navigates auth flows → downloads JSON exports

**Mitigations:**
- Enforce `ExtensionInstallBlocklist` for extensions with `webRequest` in managed Chrome deployments
- Require admin approval for unpacked extension loads via `DeveloperToolsDisabled` policy
- Log and alert on `chrome.downloads` API usage (data exfiltration vector)

#### 2. **Network Traffic Anomalies**

While this specific tool does **not** exfiltrate (all processing is local), real-world credential phishing flows exhibit distinct patterns:

**Detection:**
- Unexpected login flows to newly-registered or lookalike domains
- TLS certificate mismatches for known authentication endpoints
- Phishing infrastructure often uses reverse proxies (Evilginx, Modlishka) - look for:
  - Redirect chains with unusual intermediary domains
  - Cookie forwarding from attacker-controlled domains to legitimate IdPs
  - Session fixation: same session ID pre/post authentication

**Mitigations:**
- Enforce certificate pinning for critical authentication domains
- Monitor DNS for phishing variants of your organization's auth domains
- Deploy FIDO2/WebAuthn (phishing-resistant MFA) to break credential replay attacks

#### 3. **Endpoint Telemetry**

Extensions like this leave artifacts on developer/research endpoints:

**Detection:**
- `chrome.storage.local` persistence of captured session data
- JSON/YAML/Markdown exports in Downloads folder with naming patterns like `lab-capture-*.json`, `*-phishlet.yaml`
- Node.js process execution of generator scripts (`phishlet-generator.js`, `cli.js`)
- Git repositories containing `testdata/`, `generators/`, Evilginx schemas

**Mitigations:**
- EDR monitoring for phishing kit artifacts (YAML phishlets, Evilginx configs)
- DLP rules for Evilginx-format YAML (`.yaml` files with `auth_tokens`, `credentials.username.key`)
- Audit developer endpoints for offensive tooling; segregate pentest/research VMs

#### 4. **Phishing Kit Signatures**

Generated phishlets have distinctive structure:

**Detection:**
- YAML files with Evilginx 2.3.0 schema (`min_ver: "2.3.0"`, `proxy_hosts`, `auth_tokens`, `sub_filters`)
- Phishlet domains matching eTLD+1 of your organization's IdP (`login.idp.yourorg.com` → `idp.yourorg.com` in `proxy_hosts`)
- Comment headers: `# Generated by Chrome MV3 Lab Kit` or similar tool attribution

**Mitigations:**
- Threat intelligence sharing: Report phishing kits targeting your organization's auth flows
- Preemptive domain monitoring: Register lookalike domains before attackers do
- Coordinate with domain registrars/hosting providers to take down active phishing infrastructure

#### 5. **User Behavior Analytics**

Credential theft campaigns exploiting generated phishlets exhibit behavioral patterns:

**Detection:**
- Login attempts from:
  - Geographies/ASNs inconsistent with user's normal profile
  - Hosting provider IPs (Evilginx often deployed on VPS)
  - Tor exit nodes or anonymization services
- Session anomalies:
  - Rapid session token reuse across multiple IPs
  - Login success followed by unusual API access patterns (data exfiltration, privilege escalation)

**Mitigations:**
- Risk-based MFA challenges on anomalous login signals
- Session binding to IP/User-Agent fingerprints (with care for legitimate roaming users)
- FIDO2/WebAuthn bypasses credential theft entirely (phishing-resistant)

#### 6. **Lab Environment Containment**

This tool is designed for **authorized lab use** - ensure offensive research stays contained:

**Detection:**
- Unauthorized use against production systems (insider threat scenario)
- Phishlet deployment against live users without SOC awareness
- Credentials captured in lab exercises leaked to unencrypted storage

**Mitigations:**
- Segregate offensive research networks from production
- Require ticketing/approval for auth-flow testing engagements
- Data handling: Encrypt lab captures, auto-purge after engagement, strip from public repos

## Attacker OPSEC Implications

If this tool (or similar) is used offensively:

- **Artifacts**: Extension files, captured JSON, generated YAML on attacker-controlled systems
- **Network**: Phishing proxy infrastructure (Evilginx server) visible to defenders
- **Human**: Social engineering (lure delivery) is the weakest link - not the phishlet quality

**For Red Teams / Authorized Pentesters:**
- Coordinate with client SOC before launching credential capture exercises
- Use unique identifiers in phishlets to distinguish authorized tests from real attacks
- Provide detection signatures to the client as part of engagement deliverables

## Responsible Disclosure

If you discover this tool (or generated artifacts) in use against unauthorized targets:
- **Report to affected organization's security team** (not public disclosure)
- **Preserve evidence** (logs, phishlet YAML, captured data) for incident response
- **Coordinate takedown** with hosting providers, domain registrars, law enforcement as appropriate

---

**Defender Priority:** Deploy phishing-resistant MFA (FIDO2/WebAuthn) to neutralize credential phishing scaffolds like this. Technical phishing kit quality is increasingly irrelevant when the attack vector (credential reuse) is eliminated.
