 # Chrome-MV3-Kit Operational Constraints

## Runtime Environment

1. The tool must be designed to run on the Chrome browser.
2. The tool must have the necessary permissions to access browser authentication HTTP flows and save static HTML snapshots.
3. The tool must be able to run in an offline/air-gap environment.

## Secrets & Evidence Handling

1. The tool must not store any sensitive data, such as passwords, in plain text.
2. The tool must not commit any sensitive data to the repository.
3. The OPSEC Reviewer must document any detection-relevant artifacts generated by the tool.

## Operator Workflow

1. The tool must be easily installable and uninstallable from the Chrome Web Store.
2. The tool must provide a user-friendly interface for operators to start and stop data capture, generate phishlets, and save static HTML snapshots.

## Safety Defaults

1. The tool must have a dry-run mode that allows operators to test the tool's functionality without capturing or modifying any data.
2. The tool must have an allowlist of domains that it is allowed to capture data from.
3. The tool must prompt operators to confirm any potentially destructive actions, such as generating a phishlet.

## Degradation Modes

1. The tool must be able to function offline, with the ability to resume data capture and phishlet generation when online.
2. The tool must handle partial failure gracefully, with the ability to continue data capture and phishlet generation even if some components fail.
