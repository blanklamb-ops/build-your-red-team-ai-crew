 # Empire-Advisor Operational Constraints

## Runtime Environment

1. The tool should be compatible with the Empire platform, which primarily runs on Windows.
2. The tool should operate with the same privileges as the Empire agent.
3. The tool should be able to operate in a network environment with limited outbound connections for air-gap environments.

## Secrets & Evidence Handling

1. The tool should never commit sensitive data such as command history, scoring engine rules, or suggestion engine local knowledge base to the repository.
2. The tool should handle all sensitive data securely, using appropriate encryption and access controls.
3. The OPSEC Reviewer must document any detection-relevant artifacts generated by the tool.

## Operator Workflow

1. The tool should be invoked as a plugin or module within the Empire interface.
2. The tool should provide clear and intuitive user interface for operators to submit commands, view scores, and select alternatives.

## Safety Defaults

1. The tool should operate in a dry-run mode by default, allowing operators to preview the scores and suggestions without executing commands.
2. The tool should allow operators to define an allowlist of commands that are always executed without scoring or suggestion.
3. The tool should require explicit confirmation from operators before executing commands with scores below a certain threshold.

## Degradation Modes

1. If the tool is unable to connect to the internet, it should operate in offline mode, using the local scoring engine rules and suggestion engine local knowledge base.
2. In case of partial failure, the tool should continue to operate with the available functionality, providing scores and suggestions based on the available data.

## Plan Deltas

1. The Architect must ensure that the Empire Adapter module follows Empire plugin conventions or provides a shim with compatibility notes.
2. The Architect must ensure that the Scoring Engine module uses a transparent and documented heuristic for scoring commands.
3. The Architect must ensure that the Suggestion Engine module uses a local knowledge base that includes documented alternative commands with citations.
4. The Architect must ensure that the tool keeps humans in control by never auto-executing alternatives and providing manual review and approval of suggested alternatives.
5. The Architect must ensure that the tool archives scanner outputs in a secure and durable manner.
