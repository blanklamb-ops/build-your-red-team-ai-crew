# OPSEC Card for After-Action Collector

## Summary

The After-Action Collector is a tool designed to generate two reports: a client-facing report and an internal learning summary. It ingests various log formats and operator decision logs, correlates events with decisions, and produces structured reports.

## Operator Risks

- **Improper Log File Handling:** Operators should ensure that the log files provided to the tool are legitimate and authorized. Improper handling of log files could lead to unauthorized access or exposure of sensitive information.
- **Inadequate Decision Log:** The tool's effectiveness relies on the quality and completeness of the decision log. If the decision log is incomplete or contains erroneous information, the reports generated by the tool may be misleading or incorrect.
- **Unintended Data Exposure:** The tool's redactor module uses regular expressions to identify and redact sensitive information. If the regular expressions in the redaction configuration file are not properly defined, the tool may fail to redact all sensitive information, potentially exposing it in the reports.
- **Insecure Report Generation:** The tool currently supports generating reports in Markdown, PDF, and HTML formats. Operators should be aware that generating reports in PDF or HTML format may expose the tool to additional risks, such as the execution of malicious code.

## Artifacts Left Behind

- **Log Files:** The tool reads log files from the file system. Depending on the tool's configuration, these files may be left behind after the tool has finished processing them.
- **Redaction Configuration File:** The tool uses a redaction configuration file to determine which information to redact from the reports. This file may be left behind on the file system after the tool has finished processing it.
- **Report Files:** The tool generates report files in the Markdown, PDF, and HTML formats. These files may be left behind on the file system after the tool has finished generating them.

## Safer Operating Guidance

- **Log File Handling:** Operators should ensure that the log files provided to the tool are legitimate and authorized. Operators should also ensure that the tool is configured to delete log files after they have been processed.
- **Decision Log:** Operators should ensure that the decision log provided to the tool is complete and accurate. Operators should also ensure that the tool is configured to delete the decision log after it has been processed.
- **Redaction Configuration File:** Operators should ensure that the redaction configuration file is properly defined and up-to-date. Operators should also ensure that the tool is configured to delete the redaction configuration file after it has been processed.
- **Report Generation:** Operators should generate reports in the Markdown format whenever possible. Operators should avoid generating reports in the PDF or HTML formats, as these formats may expose the tool to additional risks. Operators should also ensure that the tool is configured to delete report files after they have been generated.

## Detection Recommendations

- **Unauthorized Log File Access:** Monitor file system access for unauthorized access to log files.
- **Incomplete or Erroneous Decision Logs:** Monitor the tool's decision log for any signs of incompleteness or erroneous information.
- **Inadequate Redaction:** Monitor the tool's report files for any signs of inadequate redaction of sensitive information.
- **Unauthorized Report Generation:** Monitor the tool's report generation process for any signs of unauthorized report generation.
